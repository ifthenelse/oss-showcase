# Branding and art direction

Run this stage before the README glow-up. Read existing design decisions and approved assets first. For a refresh, reuse the verified palette and mark unless their inputs or intended use changed. Record decisions in `.agents/brand-guidelines.md` using the supplied template.

1. **Palette.** Use existing colors or propose a small palette based on the product and audience. Give each color a role and a hex value. Check text, links and visible focus against their backgrounds. Check marks on light and dark canvases. Resolve or approve the palette under the current execution scope before proposing new artwork.
2. **Logo and variants.** Use [logo-design](https://github.com/kaankiziltug/logo-design-skill) if available. Start with the approved palette and existing mark, or show small-size concept previews before finalizing a new mark. Capture the decision before exporting, unless the user delegated concept selection. Test at 16 and 32 px and in one color. Export only the assets consumed by the showcase. Use a text wordmark if no mark is approved or export tools are unavailable.
3. **Art direction.** Use [frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design) to carry the palette, typography and logo into the README and landing page. Pick one focal point that represents the real product, such as a fixture demo or a concrete result. Keep the quickstart easy to find. Use [web-design-guidelines](https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines) to review contrast, keyboard focus, responsive layout and media during refinement. If a supporting skill is unavailable, use the existing template and check those conditions manually. Follow the [stage routing rules](stages.md) for tool discovery.

## Asset destinations

- Put reviewed public logo and favicon files under `docs/assets/` and register them as the `logo` and `favicon` roles in `.agents/product-facts.json`. Reuse the approved mark in the README header and Pages header. Check custom templates for both slots. Register a reviewed social preview only if used.
- For **Codex**, optional `agents/openai.yaml` metadata can reference bundled `interface.icon_small` and `interface.icon_large` assets relative to the skill directory. Verify the chosen install path includes the metadata and both assets before claiming support. [Codex interface metadata](https://github.com/openai/codex/blob/main/codex-rs/skills/src/assets/samples/skill-creator/references/openai_yaml.md)
- For **Claude Code** and **GitHub Copilot**, keep `SKILL.md` portable. The documented skill formats do not expose a per-skill icon. Anthropic's plugin directory has a separate listing icon for published plugins. [Claude Code skills](https://code.claude.com/docs/en/skills) · [Claude plugin manifest](https://code.claude.com/docs/en/plugins/manifest-reference) · [GitHub Copilot skills](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills)

Keep unpublished concepts and review screenshots outside the public tree. Record tools, decisions, approved assets and deferred exports in the handoff. If the user skips branding, record the skip and continue the README with existing approved assets or the text wordmark.
