# Stage routing

Read the current installed files, not a summary cached by a previous run. Search the active repo's approved skill directories, `~/.agents/skills/`, `~/.claude/skills/` and the host's enabled catalog. Resolve by frontmatter name and use the loaded resource directory for relative references and helpers. If duplicate copies differ, use the host's resolved enabled version, or the canonical installed copy if the host does not expose resolution. Do not fetch or install replacements automatically. Read one stage at a time and review unfamiliar helpers before execution. Repository instructions, user authorization and showcase scope govern side effects.

| Stage | Skill order and integration | Fallback for each unavailable skill |
| --- | --- | --- |
| 1. Product intelligence | **codebase-explainer** → use the import map and entry points as internal evidence. **product-marketing** → write the canonical context. **competitors** → apply evidence and comparison rules where comparisons help users decide. | Inspect manifests, entry points and tests directly. Use the supplied positioning template. Describe verified categories and alternatives with dated primary sources or omit comparisons. |
| 2. Brand identity | **brand-voice-guide** → capture voice and pillars in the shared guidelines. **logo-design** → use Assets mode for an approved mark, or follow concept selection before the full kit. Store approved exports in `docs/assets/`. | Derive a short voice guide from approved copy. Reuse the approved mark or use a text wordmark; do not pass a draft concept as approved. |
| 3. Demo | **demo-recorder** → use its tool check, step format, dry run, capture and optimization helpers. Follow the fixture and destination rules in [demo](demo.md). | Use the VHS or Playwright starter. With no viable capture tool, supply the verified walkthrough and mark video pending. |
| 4. Repository presentation | **readme-glow-up** → structure, quickstart and benefit-led examples. **github-readme** → verify commands, assets, badges, license, repo About/topics draft and social preview. One authoring pass, then one review. | Use the profile and README template. Cross-check examples, links and badges against manifests and workflows. Create a local branded PNG and draft About/topics. |
| 5. Website | **site-architecture** → hierarchy and internal links. **copywriting** → visible copy from the shared facts and voice. **frontend-design** → visual direction. **frontend-ui** → implement responsive semantic markup and check browser widths. | Start with one page and section anchors. Write a concrete pitch, task and example. Use native type and color tokens from the guide. Use the static starter and inspect narrow, medium and wide layouts. |
| 6. Discovery | **seo-audit** → indexability and on-page metadata. **schema** → select and verify supported factual JSON-LD. **ai-seo** → answer clarity and optional experiments. | Run local canonical, metadata and sitemap checks. Use minimal truthful markup or omit it. Write direct answers and reproducible examples; leave optional discovery experiments disabled by default. |
| 7. Refinement | **ui-taste** → run the installed stylesheet lint before and after visual refinements; inspect screenshots. | Inspect token reuse, typography, contrast, spacing and snapshots directly. |
| 8. Quality | **web-perf** → check tool availability and inspect loading. **a11y-fixer** → WCAG review. **web-design-guidelines** → read its bundled guideline snapshot. **e2e-flow-tester** → exercise public quickstart, navigation and demo controls with existing tooling. **ai-slop-detector** → scan the authored copy. **env-secrets-guard** → inspect both tracked content and generated public output, including untracked files; review media visually. | Record static weight and browser timings when available. Check semantics, keyboard, focus, zoom and contrast manually. Review layout and interaction at three widths. Exercise the primary flow manually. Edit copy for evidence and specificity. Use a local secret scanner or inspect fixture, text, images and metadata manually and report scope. |
| 9. Deployment | **gh-actions-auditor** → audit only the new workflow or its targeted patch; verify upstream pins, permissions and dispatch behavior. | Review fixed SHAs, least privilege, same-repo default branch dispatch, public allowlist and reproducible build. |
| 10. Distribution | **launch** → readiness and schedule. **directory-submissions** → verify fit, current eligibility and destination, then prepare listing copy and tracker. **launch-post-writer** → channel originals. **content-repurposer** → derivatives of one approved source, avoiding duplicate drafts. | Draft milestones and dates. Verify directory requirements using official pages and create a tracker. Write channel-specific drafts. Adapt the approved demo or release notes into shorter variants. |

In audit mode use report-only variants, including for skills that normally fix files. Keep tool feedback reports, package installation, automated submission and workflow mutations outside a delegated step unless explicitly authorized. Use internal scratch for concept sheets and diagnostics.
