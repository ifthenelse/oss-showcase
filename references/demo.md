# Reproducible demo

Choose one real task with an observable result, ideally 10 to 25 seconds. Use VHS for terminal flows and Playwright for web apps. MCP, skill, plugin and library projects choose the actual supported client, host or runner. Prefer a fixture and an isolated runtime with disposable profile, sanitized prompt, no inherited credentials, and no personal accounts. Constrain network and filesystem access to what the fixture needs. Use synthetic seeded records. Keep commands, data, tool versions and expected success assertions in `.agents/showcase/demo/` or the project's existing demo source location. Never put source recipes, raw recordings, traces or browser profiles in the public tree.

1. Load the installed demo-recorder skill and use its tool check. Pin the recorder/runtime versions locally or record exact tested versions. Run the scenario without recording and assert the expected state or exact output using existing tests or a fixture check.
2. Use the installed helper to generate a tape or browser recording script. Fallback CLI recipe: copy the bundled `templates/demo.tape`, create `demo-command.sh` with the reviewed fixture command, then run `vhs demo.tape` inside a scratch copy of the fixture. Adapt the wait to the real command or switch to the helper's prompt wait. Run with an isolated shell environment and a sanitized prompt. Fallback web recipe: adapt `templates/demo.cjs` to the verified flow, replacing the explicit template stop with locators and final-state assertions and enabling the close/save calls. Run `node demo.cjs http://127.0.0.1:PORT` from the scratch recording directory with access to an existing local Playwright installation and browser binaries. Use Playwright 1.48 or later for WebSocket routing. Apply environment-level network restrictions for scripts or browsers with additional network channels.
3. Inspect the whole capture and output metadata for credentials, identifiers, production URLs, host paths and personal data. Use ffmpeg or the installed helper to compress if needed, then copy only the reviewed public GIF or video and optional poster to `docs/assets/`. Keep a textual walkthrough or caption. For spoken essential content, include equivalent captions or transcript. Prefer silent recording.
4. Register the exact shared asset path and caption. The starter embeds GIFs in the README and links to animation on the website. It embeds video on the website with playback controls and links the same video from the README. Keep validated options consistent with accessibility needs. Preserve approved old recordings until the replacement passes review. Refresh only when the recorded flow, fixture, displayed output or recipe really requires it.
