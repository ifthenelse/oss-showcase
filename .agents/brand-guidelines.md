# OSS Showcase brand guidelines

## Palette

Use a dark default on GitHub Pages. Keep the accent for links, focus, and the demo frame. On a light GitHub canvas, use deep pine for the mark. Give fixed-background assets their own canvas when the surrounding theme is unknown.

| Role | Color | Use |
| --- | --- | --- |
| Canvas | `#10191A` | Page and dark artwork backgrounds |
| Panel | `#192626` | The demo and command examples |
| Primary text | `#F0F6EF` | Headings and key copy |
| Secondary text | `#B9C9C2` | Descriptions and captions |
| Border | `#627B73` | Dividers and container edges |
| Accent | `#D6FA78` | Links, focus outlines, and a single highlight |
| Deep pine | `#20352E` | Mark and accent on light canvases |

## Logo brief

Explore a terminal prompt opening into a frame. The frame should also read as a small display on its own. Test the symbol at 16 and 32 pixels, in one color, and on dark and light surfaces. Use the same mark for the README lockup, Pages header, favicon, and supported skill icons.

## Art direction

Use a large system-font wordmark and reserve monospace for commands. Let the real demo carry the hero, with its first confirmation as the preferred still when available. Keep the install command visible and playback user-initiated. Reuse that same moment in a share card with a short headline and the mark.

Use plain technical English. Lead with a task maintainers can verify and caption recordings with the client, the task, and the observed outcome.
